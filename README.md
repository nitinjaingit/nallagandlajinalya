# Shree Digambar Jinalya, Nallagandla, Hyderabad Website

A professional, responsive, database-free temple website. It uses plain HTML, CSS, and JavaScript, so there is no build step or server-side API.

## Preview

Open `index.html` directly in a browser. The website has separate pages for Home, Events, About, Gallery, Visit, Contact, and Donation.

## Add Your Photos

1. Open `manage-images.html` in Chrome or Edge.
2. Choose or drag in one or more JPG, PNG, or WebP photos.
3. Edit captions, arrange the order, and select a home-page photo.
4. Choose **Preview gallery** to check the result in the same browser.
5. Choose **Save website file** and save over the existing `gallery-data.js` in this folder.

The manager resizes large images to a maximum of 1600 pixels and compresses them for faster loading. The generated `gallery-data.js` contains the photos, so publishing remains file-based and does not require image hosting or a database.

As an alternative, put image files in `assets/images` and reference those paths directly from `content.js`.

## Update Content

All frequently changed content is in `content.js`:

- Temple name, description, timings, address, phone, and email
- Announcement ticker messages
- Upcoming and past events
- Donation and map links

Gallery images and captions are stored in `gallery-data.js`. This file is generated by the photo manager and should normally not be edited by hand.

## Maintain the Website Assistant

The assistant uses two files:

- `bot-sources.js` lists the approved JavaScript data files that the assistant may search.
- `site-assistant.js` loads, indexes, searches, and displays information from those files.

Website content should remain in its existing data file. Do not copy changing website information into `site-assistant.js`.

### Update Existing Bot Information

The following sources are already registered in `bot-sources.js`:

| Data file | Searchable information |
| --- | --- |
| `content.js` | Temple details, timings, contacts, announcements, events, and donations |
| `festival-data.js` | Jain Darpan dates and Hindi festival information |
| `gallery-data.js` | Gallery captions and image descriptions |
| `temples.js` | Regional temple names, addresses, and contact details |

To update this information:

1. Edit the appropriate data file.
2. Keep the same `window` global name already used by that file.
3. Publish the changed file with the rest of the website.
4. Refresh the website. Use a hard refresh if the browser has cached an older file.

The assistant rebuilds its in-browser search records each time a page opens. There is no bot training, database update, or separate search-index update.

### Add a New Bot Data File

New searchable data must be exposed through a named `window` global. Objects and arrays can contain English, Hindi, or other Unicode text:

```javascript
window.MY_WEBSITE_DATA = [
	{ title: "Example", description: "English, हिन्दी, or other Unicode text" }
];
```

Register the file in `SITE_ASSISTANT_SOURCES` inside `bot-sources.js`:

```javascript
{
	src: "my-data.js",
	globals: ["MY_WEBSITE_DATA"],
	label: "My website data",
	url: "related-page.html"
}
```

The fields mean:

- `src`: Local JavaScript data file to load. External URLs and parent-directory paths are rejected.
- `globals`: One or more `window` variable names containing searchable data.
- `label`: Human-readable name used for records that do not contain their own title or name.
- `url`: Website page opened when a visitor selects a matching result.

After registration, the assistant loads the file when necessary and recursively indexes its objects and arrays. No change to `site-assistant.js` is required.

### Multilingual Content

Store multilingual text directly in the data object using UTF-8, as the existing files do. The assistant preserves Unicode letters when normalizing and searching, so visitors can search using the same language and script used in the data. For the best matching, include useful names and descriptions in each language visitors are expected to type.

The assistant performs retrieval, not automatic translation. A Hindi query finds Hindi terms present in the registered data, but it does not translate unrelated English text into Hindi.

### Content That Does Not Update Automatically

Text written only inside an HTML file is not searched across the entire website. To make frequently changed HTML information searchable, move the value into a registered JavaScript data object and render the same value on the page.

`site-assistant.js` currently contains a few stable summaries and visitor-guidance records. If the equivalent wording on the Visit, Donate, Gallery, Festival, or Temple pages changes, update those summaries as well, or move that wording into `content.js` so both the page and assistant use one source of truth.

### Safety and Testing

- Register only trusted data files owned by this website.
- Do not register controllers such as `app.js`, `festival.js`, `event-details.js`, `manager.js`, or `shared-layout.js`; they modify pages instead of providing standalone data.
- Do not place private information in a registered file. All static website JavaScript is publicly downloadable.
- After changing a source, search for a distinctive updated phrase in the assistant and open its result link.
- After adding a source, test it from a page that does not already load that data file to confirm on-demand loading works.

## Publish

Upload the complete folder to any static host such as GitHub Pages, Azure Static Web Apps, Netlify, Cloudflare Pages, or a traditional web host. No database is required.

## Recommended Content Before Launch

- Replace the sample temple name and contact details.
- Add original temple and event photographs with meaningful captions using the photo manager.
- Confirm daily and festival timings.
- Add the committee-approved donation method and receipt instructions.
- Add social media links only for actively maintained accounts.
- Add a privacy note if a future form collects visitor information.
